# Bid Hub Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One Bid Hub page per bid (`/bid/<id>`) that merges the pipeline drawer and estimating workspace, with fixed file viewing, upgraded comparables surfaced at bid creation, and contacts showing all bid stages.

**Architecture:** React 18 + react-router-dom v6 frontend (view derived from URL segments in `App.tsx` `renderView()` switch — no nested routes), Express + pg backend, Postgres migrations in `database/migrations/` run by `backend/src/migrate.ts`. New `features/bid-hub/` feature folder hosts the page; existing `PcWorkspaceView` and `BidCompare` are re-mounted inside it, not rewritten.

**Tech Stack:** TypeScript, React 18, Vite, vitest (+ @testing-library/react, happy-dom on frontend; supertest + real-Postgres-with-skip harness on backend), Express, pg, Cloudinary/Drive/base64 document storage. New frontend deps: `xlsx` (SheetJS), `mammoth`.

## Global Constraints

- Spec: `docs/superpowers/specs/2026-07-28-bid-hub-design.md`.
- All paths relative to repo root `~/projects/Electrical-program`.
- Frontend checks: `cd frontend && npm run typecheck && npm test`. Backend checks: `cd backend && npm run typecheck && npm test` (integration tests skip without local Postgres — that is OK; they run in CI).
- Pre-commit hook may require a fresh pytest stamp in OTHER repos — not this one; commit normally.
- Gen pipeline (`GenDetailDrawer`, gen cards) is untouched. Elec only.
- Bid stages are exactly `due | submitted | awarded | lost` (`database/migrations/002_create_bids.sql:11`). Gen stages differ — never mix.
- Existing UI patterns: segmented pill tab strip from `frontend/src/features/gen-pipeline/GenDetailDrawer.tsx:160-170`; CSS vars `var(--surface2)`, `var(--border2)`, `var(--text)`, `var(--text2)`, `var(--text3)`, `var(--accent)` (note: `--accent` must exist in the stylesheet before use — historical gotcha; use `var(--blue)` style tokens already present in the file you're editing, copy what neighboring code uses).

- Commits: one per task, message style matches repo history (imperative, plain, no scope prefixes — see `git log --oneline`).
